## 📌 About

**OSINT Roadmap** is a structured learning guide for people who want to understand Open Source Intelligence in a practical, legal, and professional way.

The goal of this repository is not to collect random tools.
The goal is to build a clear learning path that explains how to think, investigate, verify, document, and report findings responsibly.

This roadmap focuses on:

* Real-world OSINT workflows
* Legal and ethical research methods
* Source verification
* Evidence handling
* Documentation and reporting
* Career-oriented investigation skills
* Practical case studies
* Beginner-to-advanced learning phases

## 🧩 Learning Path

### 1. Foundations

Start with the basics before using advanced tools.

Topics:

* What OSINT means
* Public information vs private information
* Legal boundaries
* Search engine techniques
* Source reliability
* Basic privacy and OPSEC
* Documentation habits

Recommended focus:

```text
Understand the process before collecting data.
```

---

### 2. Search & Discovery

Learn how to find useful public information without crossing legal or ethical limits.

Topics:

* Advanced search operators
* Website discovery
* Public records
* News and archive research
* Username research
* Domain and website footprinting
* Social media public profile analysis

Skills to build:

* Writing precise search queries
* Comparing multiple sources
* Saving useful references
* Avoiding false assumptions

---

### 3. Verification & Analysis

OSINT is not only about finding information.
The most important part is proving whether the information is reliable.

Topics:

* Source validation
* Cross-checking information
* Timeline building
* Image and video verification
* Metadata awareness
* Geolocation basics
* Link analysis
* Confidence levels

Example confidence levels:

| Level  | Meaning                                                              |
| ------ | -------------------------------------------------------------------- |
| Low    | Information is weak or supported by one source only                  |
| Medium | Information is supported by multiple sources but not fully confirmed |
| High   | Information is verified through strong and independent sources       |

---

### 4. Documentation & Reporting

A good OSINT investigation must be readable, organized, and defensible.

A basic OSINT report should include:

* Objective
* Scope
* Methodology
* Sources used
* Findings
* Evidence
* Confidence level
* Limitations
* Final conclusion

Simple report structure:

```text
1. Objective
2. Scope
3. Methodology
4. Findings
5. Evidence
6. Analysis
7. Limitations
8. Conclusion
```

---

### 5. Advanced OSINT

After learning the basics, move into more specialized areas.

Advanced topics:

* Threat intelligence
* Digital footprint analysis
* Infrastructure research
* Breach data awareness
* Dark web awareness without illegal access
* Social network mapping
* Business intelligence
* Geospatial analysis
* Incident support research

Important rule:

```text
Advanced OSINT should still stay legal, ethical, and evidence-based.
```

## 🔁 OSINT Workflow

A clean OSINT workflow usually follows this order:

```text
Define Objective
      ↓
Set Scope
      ↓
Collect Public Information
      ↓
Verify Sources
      ↓
Organize Evidence
      ↓
Analyze Findings
      ↓
Write Report
      ↓
Review Limitations
```

### Example Objective

```text
Verify whether a public profile, domain, or online claim is connected to a specific public source.
```

### Example Scope

```text
Only public sources.
No account bypassing.
No private access.
No impersonation.
No harassment.
```

## 🧪 Practical Case Studies

Use small, legal practice cases to build skill.

### Case Study 1: Verify a Public Claim

Goal:

```text
Check whether a public online claim is supported by reliable sources.
```

Steps:

1. Save the original claim.
2. Identify the source.
3. Search for independent confirmation.
4. Compare dates, names, and context.
5. Write a short conclusion with confidence level.

---

### Case Study 2: Analyze a Public Website

Goal:

```text
Understand the public footprint of a website.
```

Steps:

1. Review the website manually.
2. Check public WHOIS and DNS data.
3. Review archive history.
4. Identify visible technologies.
5. Document only public information.

---

### Case Study 3: Verify an Image Location

Goal:

```text
Check whether an image location can be verified from public visual clues.
```

Steps:

1. Identify signs, buildings, roads, or landmarks.
2. Compare with maps and public imagery.
3. Check shadows, weather, and environment.
4. Record findings and uncertainty.
5. Avoid claiming more than the evidence supports.

## 📝 Reporting & Documentation

A professional OSINT report should be clear and careful.

### Good Reporting Rules

* Separate facts from assumptions.
* Include source links.
* Add timestamps.
* Mention confidence level.
* Explain limitations.
* Do not overstate conclusions.
* Keep the language neutral.

### Example Finding Format

```text
Finding:
A public profile appears to use the same username as another public account.

Evidence:
- Source 1: URL + timestamp
- Source 2: URL + timestamp

Confidence:
Medium

Limitations:
The accounts share a username, but this alone does not prove ownership.
```

## ⚖️ Ethics & Law

OSINT relies on publicly available information only.

Allowed:

* Searching public websites
* Reviewing public social media content
* Checking public records
* Using search engines
* Archiving public pages for documentation
* Comparing public information

Not allowed:

* Unauthorized access
* Password guessing
* Account takeover
* Impersonation
* Social engineering
* Doxxing
* Harassment
* Privacy violations
* Bypassing platform restrictions

Core rule:

```text
If access requires deception, intrusion, or bypassing security, it is not ethical OSINT.
```

## 📚 Recommended Practice

To improve over time:

* Practice with public and legal examples.
* Build small investigation reports.
* Keep a personal OSINT notebook.
* Review old reports and improve them.
* Learn how to explain uncertainty.
* Focus on evidence, not assumptions.
* Avoid relying on one tool or one source.

Weekly practice idea:

```text
Pick one public topic.
Collect 5 public sources.
Verify the strongest claim.
Write a one-page report.
```
