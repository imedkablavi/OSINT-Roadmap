# OSINT Roadmap Growth Playbook

This document is the operating plan for making the project easier to discover and worth revisiting.

## 1. Search positioning

Primary search intents to own over time:

- OSINT roadmap
- learn OSINT
- OSINT tools
- OSINT browser extensions
- GEOINT roadmap / geolocation OSINT
- cyber threat intelligence OSINT
- digital footprint investigation
- company investigation OSINT
- OSINT بالعربي / تعلم OSINT
- Türkçe OSINT / OSINT öğrenme

Do not keyword-stuff. Each search phrase should map to a genuinely useful page or guide.

## 2. Publish useful pages, not thin pages

Every public landing page should answer a distinct user question and link to deeper repository material. Expand pages when there is enough original material to justify it.

Good future pages:

- source verification checklist
- reverse image search workflow
- OSINT report template
- passive domain investigation
- username attribution checklist
- public-record research by country/region
- investigation note examples
- monthly tool changes

## 3. Recurring reasons to return

Use a predictable cadence instead of large, rare rewrites.

Suggested rhythm:

- Weekly: review 5–10 external links and one tool/category
- Every 2 weeks: add or improve one practical lab/playbook
- Monthly: publish an `OSINT Roadmap Update` summarizing new tools, removed links and new learning material
- Quarterly: review the roadmap structure and skill matrix

Keep the RSS feed updated when publishing meaningful site changes.

## 4. Distribution loop

For every substantial release, create one useful derivative rather than posting "please star my repo".

Examples:

- a short LinkedIn post explaining one OSINT verification mistake and linking to the relevant guide;
- a Reddit post that contributes a complete checklist or workflow first, with the repo as the source;
- a visual cheat sheet for a specific workflow;
- a Turkish or Arabic mini-guide shared in relevant cybersecurity communities;
- a release note posted to GitHub, LinkedIn and personal portfolio.

Useful content earns backlinks. Generic promotion rarely does.

## 5. Backlink targets

Seek editorial inclusion where the project actually fits:

- OSINT resource lists and awesome lists;
- university cybersecurity clubs and course resource pages;
- digital journalism / verification resource pages;
- CTI learning collections;
- Arabic and Turkish cybersecurity learning communities;
- personal blogs that compare learning roadmaps.

Do not mass-submit. Tailor each request and point to the most relevant page.

## 6. GitHub discoverability

Recommended repository description:

> Multilingual OSINT roadmap for learning open-source intelligence, GEOINT, CTI, source verification, digital footprint research, tools, labs and reporting.

Recommended topics:

`osint`, `open-source-intelligence`, `osint-tools`, `osint-resources`, `geoint`, `socmint`, `threat-intelligence`, `cti`, `digital-forensics`, `fact-checking`, `geolocation`, `cybersecurity`, `investigation`, `roadmap`, `arabic`, `turkish`

Avoid broad/misleading topics such as `hacking` unless the repository genuinely focuses on hacking.

## 7. Google setup after Pages is enabled

1. Add the GitHub Pages URL to Google Search Console.
2. Submit `/sitemap.xml`.
3. Inspect the homepage and the main topic pages.
4. Request indexing only for important pages, not every minor change.
5. Watch queries, impressions and click-through rate.
6. Rewrite titles/descriptions when a page receives impressions but poor clicks.

Also consider Bing Webmaster Tools; it can provide another source of search discovery.

## 8. Metrics that matter

Track monthly:

- organic search clicks;
- impressions by query;
- returning site visitors if privacy-friendly analytics are later added;
- GitHub stars and forks;
- external contributors;
- inbound links / referring domains;
- RSS subscribers where measurable;
- issues opened for corrections/resources.

Do not optimize only for stars. A project with search traffic, citations and contributors is healthier than a project with vanity stars and no returning use.

## 9. Content quality rules

- Prefer primary and official sources.
- Date time-sensitive content.
- Remove stale tools instead of preserving a huge dead list.
- State tool limitations.
- Separate discovery from verification.
- Keep Arabic and Turkish pages useful in their own right, not machine-translated mirrors.
- Avoid publishing sensitive personal information in examples.

## 10. 90-day target

A realistic first growth cycle:

- launch Pages and submit sitemap;
- publish 6–10 strong search-intent pages;
- ship three monthly update posts/releases;
- obtain 10 relevant editorial/community backlinks;
- add at least 6 new practical labs/playbooks;
- get 3+ external contributors;
- translate the highest-traffic advanced guides into Arabic and Turkish.

The goal is compounding discoverability, not a one-day traffic spike.
